### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**
Опишите здесь нефункциональные требования и архитектурно-значимые требования.

|**№**|**Требование**|
| :-: | :- |
|1.|Партнерский кол-центр готов получать ставки только в виде файлов, нет возможности подключить АПИ|
|2.|Актуальные данные по ставкам должны приходить каждый день в фиксированное время|
|3.|На этапе MVP данные по ставкам может отправлять вручную дежурный бэк-офиса|
### <a name="_qmphm5d6rvi3"></a>**Решение**
Требуется организовать единый подход для внутреннего и партнерского кол-центра при передаче актуальных ставок, т.е. передавать будем XLSX-файлы. 
Для сотрудников внутреннего кол-центра стоит реализовать более удобный UI просмотра ставок, чем скачивание и открытие XLSX-файла в редакторе.
### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Использование микросервиса для расчета ставок и выгрузка результатов во внешний контур с целью безопасности. В дальнейшем можно разработать и поддержать АПИ для интеграции партнерского кол-центра, когда они будут готовы, либо помочь им с внедрением апи, выполнив работы на их стороне.

**Недостатки, ограничения, риски**

* Процесс отправки файлов со ставками на внутреннюю рассылку партнерского кол-центра должен быть покрыт алертами, дежурный бэк-офиса должен следить за его работоспособностью. В случае поломки файл должен быть отправлен вручную.
* Есть риск устаревания данных по ставкам в течение дня, т.к. рассылка производится по расписанию.
